# Product Requirements Document (PRD): fleet-infra

> GitOps infrastructure for the bamr87 fleet: Terraform/HCL provisioning, a k3s cluster, and Helm charts reconciled from git.

Open work is tracked in [GitHub Issues](https://github.com/bamr87/fleet-infra/issues) and as `status: planned` entries in [features/features.yml](features/features.yml).

## 1. Overview

Infrastructure-as-code for running the fleet's services on a small k3s cluster, provisioned with Terraform and kept in sync from git with Helm and a GitOps controller.

| Version | Date | Notes |
| --- | --- | --- |
| 0.1 | 2026-10-28 | Initial requirements and phased roadmap (repo foundation). |

## 2. Goals

- Provision a reproducible k3s cluster (local VM or cloud) from Terraform
- Package fleet services as Helm charts
- Reconcile cluster state from git (Flux/Argo CD) with PR-only changes

Non-goals (near term): production hosting, paid services, anything outside the roadmap below without a PRD change.

## 3. Users

- The maintainer, learning terraform modules, state and providers, kubernetes/k3s operations by building.
- Fleet agents (hub evolution loop, backlog fan-out, `evolve` lane) that grow the repo one reviewed PR at a time.
- Fleet tie-in: Hosts fleet services (ragio-ai, fredgar-ai, law-ai, fleet-observe) and replaces ad-hoc docker compose on the bench with declarative deploys.

## 4. Requirements

Phases are the build order: an agent picks the earliest unserved requirement first.

### 4.1 Phase 1 — Foundation

- FR1: Terraform root module validates and plans with no cloud credentials (local backend)
- FR2: A base Helm chart lints cleanly and renders a namespace + deployment

### 4.2 Phase 2 — Core

- FR3: k3s cluster provisioning module for a local VM (multipass/libvirt)
- FR4: GitOps controller bootstrap that reconciles charts/ from main

### 4.3 Phase 3 — Fleet integration

- FR5: Per-service Helm charts for fleet apps (ragio-ai, fredgar-ai)
- FR6: Secrets management via SOPS/age, never plaintext in git

### 4.4 Non-functional

- NFR1: CI (`.github/workflows/ci.yml`, the fleet standard gate) passes on every PR.
- NFR2: No secrets or credentials are committed; configuration comes from environment variables.
- NFR3: Autonomous lanes are off by default, open pull requests only, and never merge.
